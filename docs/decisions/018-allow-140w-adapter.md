# 018：允許 Apple 原廠 140W 變壓器（使用者決定，協定 008-v4）

日期：2026-10-15
狀態：採用（使用者決定；在任何 008-v3 / 008-v4 的 run 之前）

## 背景

- 014（2026-10-09 使用者決定）：formal run 固定使用 Apple 原廠 70W 變壓器（`pmset -g ac` 的製造商 Apple Inc.、名稱 `70W USB-C Power Adapter`，系統回報 68 W）。
- 2026-10-15 恢復文字 workload 的重跑時，Mac 接的是 Apple 原廠 `140W USB-C Power Adapter`（系統回報 94 W）。formal 前置檢查會拒絕。
- 這時還沒有任何 run 在 008-v3（decision 017）下執行；GloVe 的 8 份是 008-v2、70W。

## 決策

使用者在 2026-10-15 22:20（台灣時間）前後選擇「**允許 140W**」：

1. formal run、閒置 load 量測與 Gate profiling 的電力條件：Apple 原廠 **70W 或 140W** 變壓器（`protocol.FORMAL_ADAPTERS`）。
2. **同一個 run 內不得更換變壓器**（前置檢查記下變壓器，每個子 process 前、子 process 期間的取樣與 run 結束時都比對），
   **一份報告只合併同一個變壓器的 run**（`report.py` 的合併檢查），與電力模式的規則相同（014 補記、016）。
3. 協定版本改為 **`008-v4`**。文字 workload 的 4 份全部在 008-v4 下重跑（017 已作廢唯一的 008-v2 文字 run）；GloVe 的報告不受影響。
4. 開始時不再看電量（使用者同時決定：只要接著電、lock 空出、機器閒置、高效能模式就開始；取代 2026-10-11 的「電量 ≥ 90% 才開始」）。

## 為什麼

- 140W 的供電比 70W 充足，不會因供電不足改變 CPU 狀態；014 規定變壓器的目的（固定、可重現的供電條件）由「同一份報告同一個變壓器」維持。

## 放棄的替代方案

- **換回 70W**：使用者選擇允許 140W。
- **不限制報告內混用變壓器**：與電力模式一樣，混用會讓同一份報告的 run 在不同的供電條件下。

## 對實驗的影響

- 文字報告的所有 run 會是 008-v4、高效能模式、140W（若之後換回 70W，換之前與之後的 run 不能合併，需另寫 decision）。
- GloVe（70W）與文字（140W）的供電條件不同；兩個資料集各自一份報告，跨資料集只比較各自的讀值，不合併 run。
