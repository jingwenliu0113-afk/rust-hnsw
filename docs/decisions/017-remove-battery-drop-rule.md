# 017：取消電量下降的作廢規則（使用者決定，協定 008-v3）

日期：2026-10-11
狀態：採用（使用者決定；在看任何文字 workload 的正式效能結果之前）

## 背景

- 014（2026-10-09 使用者決定）：「若電池在 run 中持續明顯下降，該 run 作廢並停止」。014 與補記把它實作成
  「電量比 run 期間看到的最高電量低 3 個百分點以上，run 記為 invalid 並停止」。
- 文字 workload 依 016 以高效能模式重跑 text-formal-2（`20261011T033341Z-formal`）時：電池充到 100%（`charged`）之後，
  macOS 的狀態變成 `AC attached`（接著電但不充電），約 20 分鐘內電量從 100% 回落到 96%，run 因此 invalid。
  當時整機的非受測 CPU 合計最多約 96%（受測的子 process 再加 1 個 core），遠低於 68 W 變壓器的供電，比較像 macOS 充滿後讓電量回落幾點的電池管理，
  不是供電不足。之前 `text-formal-4`（`20261010T202624Z-formal`）的 98% → 95% 也是在 `AC attached` 狀態下。
- 接著 AC 時電量回落不會讓 CPU 變慢；拔掉電源會被「必須接 AC」的檢查抓到。
- 撰寫者只看過這些 run 的狀態與電力紀錄，**沒有看過任何文字 run 的 recall、QPS、latency、build time 或記憶體**。

## 決策

使用者在 2026-10-11 12:55（台灣時間）前後選擇「**取消電量規則**」：

1. formal run 與閒置 load 量測的電力條件只剩：接 AC、Apple 原廠 70W 變壓器、電力模式為自動（0）或高效能（2）且在 run 內不變（014 與補記），
   以及同一個資料集的 run 用同一個模式（016）。電量照常記錄在 `power_samples` 與 metadata，**不再是 run 是否有效的條件**。
2. 協定版本改為 **`008-v3`**（`protocol.BATTERY_DROP_LIMIT_PCT` 移除，`protocol_record()` 改記 `battery_rule`）。
   `report.py` 拒絕合併不同協定版本的 run，所以：
   - GloVe 的 8 份（008-v2）照舊是一份完整的報告，不受影響（其中沒有任何 run 因電量規則作廢）。
   - 文字 workload 全部在 008-v3 下重跑。唯一一個 008-v2 的 complete 文字 run（text-formal-1 `20261010T112849Z-formal`）
     依本文件作廢，登記在 `report.py` 的 `VOIDED_RUNS`，報告以 `--excluded` 列出。理由是協定版本不同，與結果無關。
3. 文字 4 份以 `--powermode 2`（016）重跑。開始前電量 ≥ 90%（使用者 2026-10-11 10:25 台灣時間的指示，屬於排程條件，不是有效性條件）。
4. 閒置 load 量測（`results/idle_load/20261009T080239Z.json`，`ok`）照舊有效：它確認的是 load 門檻，與電量規則無關。

## 為什麼

- 電量規則的目的是抓「供電不足、性能可能改變」；但 Apple Silicon 在電池補電時不會降速，真正的供電中斷（拔掉電源）已有 AC 檢查。
- 3 點的門檻會被 macOS 的正常電池管理觸發，長的 run 幾乎不可能完成，而且與量測品質無關。

## 放棄的替代方案

- **改成電量低於 90% 才作廢**：使用者選擇完全取消。
- **維持規則、由使用者調整充電設定**：不確定能避免回落，而且屬於系統設定。
- **在報告中允許合併 008-v2 與 008-v3 的文字 run**：兩者的有效性規則不同；文字只有 text-1 一份 008-v2 的 complete run，重跑成本約 2 小時，選擇乾淨地重跑。

## 對實驗的影響

- 文字報告的 `--excluded`：`20261010T083544Z-formal`、`20261010T133129Z-formal`、`20261010T202624Z-formal`、`20261011T033341Z-formal`（失敗的 run），
  `20261010T183115Z-formal`、`20261010T195251Z-formal`（016）、`20261010T112849Z-formal`（本文件）。
- 文字 4 份全部重跑，約 5 小時。之後依 015 §2 做 Gate profiling（profiling 的證據條件同樣不再檢查電量）。
